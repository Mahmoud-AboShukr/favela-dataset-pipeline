# Repository Structure

This page explains how the repository is organized and how the main folders relate to the favela dataset pipeline.

The project is structured to support both:

- a **reproducible geospatial data pipeline**, and
- a **research workflow** with experiments, QC outputs, and thesis-oriented documentation.

The current repository already includes modules for polygon cleaning, AOI preparation, GHSL-based processing, mask refinement, Sentinel preprocessing, tiling, QC, and temporal-change analysis. 

---

## Top-level structure

At the root of the repository, the main components are:

- `config/` — configuration files and experiment settings
- `data/` — raw, interim, and processed datasets
- `docs/` — MkDocs documentation, methods, decisions, status notes, and thesis drafts
- `notebooks/` — exploratory analysis and visual checks
- `reports/` — progress notes, QC outputs, milestone notes, and pilot reporting
- `scripts/` — shell and PowerShell entry points for running parts of the pipeline
- `src/` — main Python source code for the pipeline
- `tests/` — lightweight tests for rasterization, alignment, and tiling
- `archive/` — older or archived code snapshots kept for reference
- `mkdocs.yml` — documentation site configuration
- `pyproject.toml`, `requirements.txt` — Python project metadata and dependencies

## `data/`

The `data/` directory is where project inputs and generated raster/vector products live.

### `data/raw/`
Stores source datasets that are not yet transformed by the pipeline.

Current examples include:

- official favela shapefile components in `data/raw/favelas_shp/`
- GHSL rasters in `data/raw/ghsl/`, including `Brasilia_2018.tif` and `Brasilia_2025.tif`
- Sentinel placeholders under `data/raw/sentinel/s1/` and `data/raw/sentinel/s2/` 

### `data/interim/`
Stores intermediate outputs generated by the pipeline.

This is currently one of the most important folders in the repo and already contains:

- `aoi/` for Brasília AOI files such as `brasilia_boundary.gpkg`
- `ghsl_clips/` for clipped GHSL rasters
- `masks/` for polygon masks, refined masks, settlement masks, threshold sweeps, and debug rasters
- `polygons_clean/` for cleaned national polygons and Brasília subsets
- `temporal_change/` for GHSL epoch comparison outputs such as growth, loss, and persistence maps 

Examples of important interim products include:

- `data/interim/polygons_clean/favelas_clean.gpkg`
- `data/interim/polygons_clean/favelas_brasilia.gpkg`
- `data/interim/masks/brasilia_polygon_mask.tif`
- `data/interim/masks/brasilia_refined_mask.tif`
- `data/interim/masks/sweeps/...`
- `data/interim/masks/test_brasilia/...`
- `data/interim/temporal_change/growth_2018_to_2025.tif`
- `data/interim/temporal_change/loss_2018_to_2025.tif`
- `data/interim/temporal_change/persistence_2018_to_2025.tif`

This folder exists as the intended destination for later-stage processed outputs, although the current pilot work is still concentrated mainly in `raw/` and `interim/`. :contentReference[oaicite:7]{index=7}

## How the repository maps to the pipeline

A simplified view of the workflow is:

1. **Raw inputs** enter through `data/raw/`
2. **Cleaning and AOI preparation** are handled in `src/labels/`, `src/aoi/`, and `src/osm/`
3. **Auxiliary raster preparation** is handled in modules such as `src/ghsl/`
4. **Refinement outputs** are written to `data/interim/masks/`
5. **QC and reporting** are written to `reports/` and documented in `docs/`
6. **Later dataset construction** is handled in `src/dataset/`, `src/sentinel/`, and `src/tiling/`

## Recommended documentation principle

When extending this repository, it is useful to keep the following distinction:

- `src/` = reusable implementation
- `scripts/` = runnable entry points
- `data/` = inputs and outputs
- `reports/` = generated reporting artifacts
- `docs/` = curated explanation of methods, experiments, and decisions
- `archive/` = historical material not part of the active pipeline

This separation will become more important as additional refinement experiments are added.
